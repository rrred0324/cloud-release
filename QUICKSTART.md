# Cloud Release — Quick Start

Get started in 5 minutes.

## Step 1: Open your project

```bash
cd /path/to/your/project
```

Make sure you're in a git repository.

## Step 2: Run cloud-release

```bash
/cloud-release
```

## Step 3: Review detection results

Cloud Release will auto-detect:

```
Project Detection Summary:
  Name: my-app
  Type: fullstack
  Branch: main

  Stacks:
    - python: fastapi
    - nodejs: vite

  Deployment target:
    Build: docker
    Deploy: docker-compose
```

Confirm or correct the detection results.

## Step 4: Follow the phases

| Phase | What happens | Your role |
|-------|-------------|-----------|
| Change Analysis | Git diff since last release | Review change summary |
| Security Audit | Scan for secrets and auth issues | Fix P0 issues if found |
| Build Verification | Run tests and builds | Review results |
| Data Sync Plan | Generate migration scripts | Choose migration strategy |
| Deployment Plan | Generate step-by-step plan | Review and approve |
| Execute | Deploy (optional) | Execute or do manually |

## Step 5: Use the output

Two files are generated by default in `releases/<date>/`:

1. **DEPLOYMENT_PLAN.md** — Follow this to deploy
2. **RELEASE_REPORT.md** — Archive this for records

## Optional: Configuration file

Create `.cloudrelease.yml` if auto-detection is wrong:

```yaml
project:
  name: "my-app"

stack:
  backend:
    language: "python"
    framework: "fastapi"
  frontend:
    framework: "react"

target:
  method: "docker"
  docker:
    compose_file: "docker-compose.yml"
```

## Common scenarios

### Scenario: Deploy to a VPS with systemd

1. Run `/cloud-release`
2. Confirm systemd as deployment target
3. Review the deployment plan
4. SSH to your server and follow the steps

### Scenario: Deploy with Docker Compose

1. Run `/cloud-release`
2. Confirm Docker as deployment target
3. Review the deployment plan
4. Run `docker compose up -d` on your server

### Scenario: Deploy frontend to Vercel

1. Run `/cloud-release`
2. Confirm Serverless (Vercel) as target
3. Review the deployment plan
4. Run `vercel --prod`
